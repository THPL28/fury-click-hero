# Security Policy

## Supported Versions

Only the latest release line on `main` is considered supported.

## Reporting a Vulnerability

Do not open public issues for vulnerabilities.

Recommended process:

1. Open a private security advisory on GitHub.
2. Include reproduction steps, impact, and affected versions.
3. Wait for maintainer confirmation before public disclosure.

## Security Controls

- Protected branches on `main` and `develop`
- Required pull request reviews
- Secret scanning workflow
- Dependabot updates
- Conventional Commits and controlled releases
